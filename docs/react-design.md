# React: визуальная система панели Allur Plant Twin

Дизайн предназначен для работающего прототипа цифрового двойника: он должен помогать находить причину остановки и сравнивать действия оператора. Тёмная боковая навигация отделяет разделы приложения от светлой рабочей области. Красный акцент выделяет главное действие, а состояния производства используют зелёный, янтарный и красный с текстовыми подписями.

Это самостоятельный интерфейс команды для хакатона, а не официальный продукт Allur. Факты из открытых источников и симуляция должны иметь отдельные подписи. Использование фирменного знака не означает одобрения проекта компанией. Базовое значение `--brand: #e52b31` является выбранным дизайнером акцентом до проверки официальных материалов, а не утверждением об официальном HEX-коде Allur.

## Структура

`src/styles.css` импортируется один раз в точке входа React. Локальные файлы Arimo находятся в `assets/fonts/`; Vite должен обработать относительные ссылки из CSS. Внешних запросов шрифтов не требуется.

```text
app-shell
├── sidebar
│   ├── brand
│   ├── nav > nav-link [is-active / aria-current="page"]
│   └── sidebar-foot
└── main-area
    ├── topbar > breadcrumb + header-actions
    └── main
        ├── page-heading > div(eyebrow, h1, page-subtitle) + source-chip
        ├── toolbar
        ├── kpi-grid > kpi-card
        ├── content-grid > panel + stack
        └── page-footer
```

Боковая навигация занимает 248 px на стандартном ноутбуке. Ширина рабочего контента ограничена 1600 px. При ширине менее 768 px навигация превращается в шесть кнопок в два ряда; отдельный дублирующий мобильный navbar не нужен.

## Контракт компонентов

| Компонент | Классы и правила |
| --- | --- |
| Навигация | `nav-link` на `button` или `a`, выбранный раздел `is-active` и `aria-current="page"`; SVG 18 px |
| Контейнер | `panel`, заголовок `panel-header`, текст `panel-title` и `panel-subtitle` |
| Сетки | `content-grid` — широкая и узкая колонки; `two-column`, `three-column`, `stack` — независимые блоки без внешних отступов |
| KPI | `kpi-grid` содержит 4 `kpi-card`; внутри `kpi-label`, `kpi-value`, `kpi-note`; единицы в `small` |
| Действия | `button button-primary`, `button button-secondary`, `button button-danger`; `button-small` — компактный вариант; `icon-button` требует доступного имени |
| Источник | `source-chip is-synthetic` для симуляции, `source-chip is-real` для проверенного открытого источника; нейтральный `source-chip` для версии/контекста |
| Схема потока | `process-map` содержит `process-stage` и `process-connector`; этапы располагаются в одну строку на широком экране и сетку 2×2 на более узком |
| Статус | `status-badge badge-running / badge-warning / badge-stopped / badge-neutral`; цвет сопровождается текстом |
| Предупреждение | `is-warning` и `is-stopped` модифицируют `process-stage`, `risk-panel`, `risk-number`, `kpi-card`, `progress-fill` |
| Прогресс | `progress-track > progress-fill`; ширина заполнения передаётся числом 0–100% |
| График | контейнер `chart`, SVG с `viewBox`; сетка `grid-line`; подписи `chart-legend` и `chart-note`; сравнения должны иметь различимые линии и текстовую легенду |
| Таблица | `table-wrap > table.line-table`; горизонтальный скролл остаётся внутри контейнера; `th` со `scope` |
| Метрика | `metric-pair` содержит подпись и значение; вариант внутри этапа процесса вертикальный |
| Риск | `risk-panel` содержит `risk-number`, `risk-reasons` и `risk-split`; вывод вероятности не заменяет сведения о доступности модели |
| Инцидент | `incident-list > incident-row`: SVG, текст с `incident-meta`, кнопка; на телефоне кнопка переносится под текст |
| Формы | `field` на связанном label, `field-grid`, `form-hint`, `error-message`; ошибка должна иметь `role="alert"` и сохранять предыдущую валидную запись |
| Контекст | `info-note`; вариант `is-warning` для значимого ограничения; длинные URL переносятся |
| Allur | `brand-facts > fact-card`, `hero-factory` с контекстом (проверенное изображение не получено), `source-list`; факт должен содержать дату и ссылку на источник |
| Сравнение | `comparison-gains > div > strong + span`, `comparison-control > label + input[type=range] + form-hint` |
| Диалог | `dialog-backdrop > dialog > dialog-header`; управление фокусом и Escape реализуются в React; можно использовать нативный `dialog.dialog` |
| Уведомление | `toast` внизу экрана; React назначает `role="status"` или `alert` по смыслу |

## Размеры и адаптация

Основной текст — 14 px, подписи — 11–12 px. Крупный KPI — 27–37 px, риск — 40–58 px. Используются регулярное и полужирное начертания Arimo. Числа выравниваются табличными цифрами.

Точки перестройки: 1280, 1024, 768 и 390 px. На 390 px: четыре KPI становятся сеткой 2×2, основные панели — одной колонкой, таблицы прокручиваются внутри контейнера, источники и формы не растягивают страницу. На обычном ноутбуке основная схема процесса и прогноз находятся рядом.

В CSS есть видимый `:focus-visible`, отключение необязательного движения при `prefers-reduced-motion` и печатный режим с сохранением основных результатов. Семантика, доступные имена, клавиатурное управление, актуальные данные и фактическая проверка размеров выполняются в React и браузерной верификации.

## Принципы подачи данных

- Факты о компании публикуются только с источником и датой, отдельно от производственных KPI симуляции.
- Для данных Scania показывается исходная задача диагностики APS; её качество не переносится на завод Allur.
- Пустое состояние модели объясняет требуемую историю или причину недоступности вместо ложного 0%.
- На всех графиках указываются единицы; на сравнениях — исходные условия и горизонт расчёта.
- Текст предупреждения должен оставаться понятным без распознавания цвета.
