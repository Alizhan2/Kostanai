# Техническое описание Allur Plant Twin

Кейс №2 — цифровой двойник автомобильного завода Allur. Прототип показывает четыре условных участка, показатели смены, инциденты, прогноз исчерпания буфера сборки и сравнение времени вмешательства.

## Архитектура и данные

Интерфейс версии 0.9 использует React 19.3.0 и CSS; Vite 8.3.2 собирает его в статические файлы `site/`. `engine.js` моделирует производственные показатели, `scenario-analysis.js` сравнивает независимые синтетические сценарии, `src/App.jsx` и компоненты `src/components/` отображают результаты. Статический HTTP-сервер только отдаёт файлы. Состояние смены сохраняется локально в браузере; подключений к MES/ERP Allur нет.

Данные заводской симуляции и обучения прогноза буфера синтетические. Лес из 64 деревьев оценивает исчерпание запаса в следующие 60 минут; рядом показаны расчёт баланса потоков и линейный тренд. На импортированных снимках обученная модель не выдаёт оценку до отдельного обучения и проверки на данных предприятия.

Отдельный диагностический модуль обучен на открытых эксплуатационных данных Scania APS. Он классифицирует неисправность APS и другого компонента грузовика. Его показатели не относятся к заводскому буферу Allur и не предсказывают время будущей поломки.

Подробности: [архитектура](architecture.md), [модель буфера](../ml/README.md), [Scania APS](../ml/APS-README.md), [проверка](verification.md).

## Использованные AI-инструменты

**OpenAI Codex** использован как помощник при разработке: анализ задачи, подготовка JavaScript/Python-кода, макетов, документации, сценариев, поиск открытого набора данных, организация обучения и проверок. Программное обучение Random Forest выполнялось локальными скриптами scikit-learn; метрики получены расчётом на отложенных данных, а не ответами генеративной модели.

**Figma** использована для редактируемых макетов, компонентов и переноса визуального оформления в интерфейс. Работа с макетами выполнялась с помощью подключённых инструментов Figma из Codex. Это средство дизайна, отдельная генеративная модель Figma в проекте не заявляется. Макеты относятся к предыдущему интерфейсу; оформление React-версии 0.8 подготовлено в коде и не представляется обновлённым файлом Figma.

**Canva** использована для создания редактируемой презентации импортом подготовленного PowerPoint. Қазақша презентация содержит 10 слайдов, пять реальных скриншотов и данные трёх участников Zhubanov team. Генеративная модель Canva не использовалась.

Приложение при использовании не обращается к Codex или другим генеративным API. Команда должна понимать представленное решение и уметь объяснить код, формулы, данные, разбиение выборок, ошибки и ограничения согласно §6.4 положения. Подготовлены [вопросы для защиты](submission/jury-questions.md); прохождение репетиции участниками ещё не подтверждено.

## Эффект и условия применения

В синтетическом двухчасовом сценарии пополнение через 30 минут предотвращает 75 минут моделируемого простоя и добавляет около 25 эквивалентных автомобилей. Денежный эффект и качество на Allur не оценены.

Для пилота потребуются подтверждённые мощности и потоки, схема участков, история остановок и вмешательств, проверка по будущему периоду, интеграция с источником данных, роли и хранение. Непубличную историю следует хранить отдельно; `ml/local/` исключён из Git и архива. Прототип не управляет оборудованием предприятия.

## Открытые сведения Allur

`data/allur-public.json` хранит факты из официального задания и ссылки на первоисточник. Доступ к корпоративным сайтам ограничен сетевой политикой среды; мощности, годовой выпуск, состав брендов и официальный логотип не подтверждены и не использованы. Авторские цвета и текстовое название интерфейса не являются официальным брендингом. Каталог не используется для обучения моделей. Подробнее — [источники](allur-public-sources.md).

## Версия 0.9: таблицы и оценка действия

`src/lib/production-csv.mjs` использует Papa Parse для разделителей и кавычек, затем проверяет схему, числа, метаданные и передаёт снимок общему движку. CSV не подтверждает происхождение данных и не включает синтетический ML на импортированных наблюдениях.

`decision-analysis.js` оценивает предотвращённые затраты по результату существующего сценария. Оба денежных поля пустые по умолчанию. Формула: простой/60 × ставка − плата за действие. Плата учитывается только при действии внутри горизонта, маржа автомобилей отдельно не добавляется. Нулевые допущения допустимы, неверные числа отклоняются. Никакого измеренного ROI Allur не заявлено.

[Обзор рынка](market-analysis.md) и закреплённые репозитории показывают основание выбора функций. ThingsBoard начиная с 4.4 использует BUSL; его код не включён. Ditto, Grafana и Node-RED рассмотрены как ориентиры/кандидаты будущей интеграции, а не установленные компоненты.
