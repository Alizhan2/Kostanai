# Техническое описание Allur Plant Twin

Кейс №2 — цифровой двойник автомобильного завода Allur. Прототип показывает четыре условных участка, показатели смены, инциденты, прогноз исчерпания буфера сборки и сравнение времени вмешательства.

## Архитектура и данные

Интерфейс использует HTML, CSS и JavaScript. `engine.js` моделирует производственные показатели, `scenario-analysis.js` сравнивает независимые синтетические сценарии, `app.js` отображает результаты. Статический HTTP-сервер только отдаёт файлы. Состояние смены сохраняется локально в браузере; подключений к MES/ERP Allur нет.

Данные заводской симуляции и обучения прогноза буфера синтетические. Лес из 64 деревьев оценивает исчерпание запаса в следующие 60 минут; рядом показаны расчёт баланса потоков и линейный тренд. На импортированных снимках обученная модель не выдаёт оценку до отдельного обучения и проверки на данных предприятия.

Отдельный диагностический модуль обучен на открытых эксплуатационных данных Scania APS. Он классифицирует неисправность APS и другого компонента грузовика. Его показатели не относятся к заводскому буферу Allur и не предсказывают время будущей поломки.

Подробности: [архитектура](architecture.md), [модель буфера](../ml/README.md), [Scania APS](../ml/APS-README.md), [проверка](verification.md).

## Использованные AI-инструменты

**OpenAI Codex** использован как помощник при разработке: анализ задачи, подготовка JavaScript/Python-кода, макетов, документации, сценариев, поиск открытого набора данных, организация обучения и проверок. Программное обучение Random Forest выполнялось локальными скриптами scikit-learn; метрики получены расчётом на отложенных данных, а не ответами генеративной модели.

**Figma** использована для редактируемых макетов, компонентов и переноса визуального оформления в интерфейс. Работа с макетами выполнялась с помощью подключённых инструментов Figma из Codex. Это средство дизайна, отдельная генеративная модель Figma в проекте не заявляется.

Приложение при использовании не обращается к Codex или другим генеративным API. Команда должна понимать представленное решение и уметь объяснить код, формулы, данные, разбиение выборок, ошибки и ограничения согласно §6.4 положения. Подготовлены [вопросы для защиты](submission/jury-questions.md); прохождение репетиции участниками ещё не подтверждено.

## Эффект и условия применения

В синтетическом двухчасовом сценарии пополнение через 30 минут предотвращает 75 минут моделируемого простоя и добавляет около 25 эквивалентных автомобилей. Денежный эффект и качество на Allur не оценены.

Для пилота потребуются подтверждённые мощности и потоки, схема участков, история остановок и вмешательств, проверка по будущему периоду, интеграция с источником данных, роли и хранение. Непубличную историю следует хранить отдельно; `ml/local/` исключён из Git и архива. Прототип не управляет оборудованием предприятия.
