# Allur Plant Twin

Рабочий веб-прототип цифрового двойника автомобильного производства для кейса №2 Qostanai AI Industry Hackathon 2026. Интерфейс на русском, адаптирован для телефона. Внешние библиотеки, ключи API и интернет для запуска не требуются.

## Дизайн

[Макеты в Figma](https://www.figma.com/design/uBCseosrNd3f8jDkTayoNc?node-id=3-78): пять основных экранов, мобильный обзор и редактируемые компоненты. Подробности передачи разработчикам — в `design/README.md`.

Интерфейс версии 0.3 перенесён на общие стили макета: крупные показатели, карта участков, отдельный прогноз остановки, история буфера и полная таблица линий. Шрифт Arimo и SVG-иконки находятся в `assets/` и работают без интернета. Подробнее — `docs/design-implementation.md`.

## Обученная модель

Версия 0.4 включает обученную ML-модель исчерпания буфера на горизонте 60 минут. Лес из 64 деревьев работает прямо в браузере рядом с расчётом баланса потоков. Обучение — на 600 синтетических сменах; заводская история пока отсутствует. Метрики, команды обучения и ограничения — в [ml/README.md](ml/README.md).

На отложенных синтетических сменах: recall 90,2%, precision 72,6%. Модель находит больше событий, но даёт больше ложных предупреждений, чем расчёт баланса; его F1 выше. Эти результаты не подтверждают качество на данных Allur.

Версия 0.5 добавляет подготовку внешней истории из CSV и обучение со сменами, разделёнными по времени. Формат и команды — в [ml/telemetry-format.md](ml/telemetry-format.md). Этот маршрут ещё не выполнялся на реальных данных.

Версия 0.6 включает отдельную диагностику на реальных открытых данных **Scania APS**: 60 000 исходных записей обучения и 16 000 оценки. Полнота — 97,1%, precision — 41,7%, ложных предупреждений — 508. Модель классифицирует компонент неисправности грузовика; её показатели не относятся к заводскому буферу или оборудованию Allur. Источники, GPL-3.0-or-later, команды и ограничения — в [ml/APS-README.md](ml/APS-README.md).

## Сравнение сценариев

В версии 0.7 откройте **Отчёты и аналитика → Что будет, если пополнить буфер?**. Выберите время действия от 0 до 120 минут: график, таблица и показатели покажут разницу между задержкой без действий и пополнением. Через 30 минут: 75 минут предотвращённого простоя и около 25 дополнительных эквивалентных автомобилей; через 60 минут: 15 минут простоя уже потеряны. Сравнение использует два независимых синтетических сценария и сохраняет текущую смену. Результат с параметрами и 25 точками графика можно скачать в JSON.

## Комплект для сдачи

Поля команды, черновик письма и ответы жюри находятся в [docs/submission/](docs/submission/README.md). Сборка архива и копии PDF:

```sh
npm run release
```

Результаты сохраняются в `dist/`. `submission-status.json` перечисляет недостающие поля и контрольные суммы. Внешняя история из `ml/local/` не включается в архив. Перед окончательной сдачей нужны авторы в презентации, публикация кода и адрес получателя.

## Запуск

Откройте `index.html` в браузере или запустите локальный сервер:

```sh
python3 -m http.server 8000
```

Перейдите на `http://localhost:8000`. При наличии Node.js можно использовать `npm start`. Устанавливать зависимости не нужно.

## Демо за 2 минуты

1. Нажмите **Сбросить**. Начальный сценарий — задержка деталей: буфер 12 комплектов, расход 20/ч, подача 4/ч. Расчётный горизонт остановки — 45 минут.
2. Нажмите **+5 минут** девять раз: буфер исчерпается, сборка остановится. Ещё один шаг увеличит простой.
3. Нажмите **Пополнить буфер**: добавятся 30 комплектов, подача восстановится до 21/ч, линия возобновит работу.
4. Перейдите в **Остановки и инциденты** и **Отчёты и аналитика**: увидите закрытые инциденты и журнал вмешательства.
5. Выберите **Дефекты окраски**, продвиньте время, откройте **Качество продукции**. Скорректируйте параметры и наблюдайте постепенное улучшение накопленного качества.
6. В **Данные и настройки** импортируйте `data/sample-production.json`. Экспортируйте снимок JSON, CSV или текстовый отчёт. В разделе отчётов доступна печать в PDF.

Автосимуляция: 5 модельных минут каждые 2,5 секунды; темп ×3 и ×6 увеличивает шаг. Шаг останавливается при открытом диалоге и на странице загрузки данных. Смена длится 12 модельных часов и начинается со снимка через 2 часа после её начала. Переключение смены создаёт новые демонстрационные данные. Снимок сохраняется в браузере; после перезагрузки история и журнал начинают новую сессию.

## Реализовано

- шесть разделов: обзор, линии, инциденты, качество, отчёты, данные;
- карта четырёх участков, карточки оборудования, фильтры;
- расчёт выпуска, загрузки, доступности и качества по состоянию модели;
- расход буфера, остановка сборки и восстановление после вмешательства;
- прогноз до исчерпания буфера по балансу потоков;
- независимый линейный тренд по истории буфера с R²;
- индекс риска с объяснением причин;
- обученный лес деревьев с калибровкой: ML-оценка исчерпания буфера на 60 минут;
- отдельная диагностика Scania APS с загрузкой JSON и исходными примерами;
- фиксация инцидентов, принятие в работу и журнал действий;
- импорт валидированного JSON, экспорт CSV/JSON/TXT и печать;
- полностью локальная работа без удалённых шрифтов и запросов.

## Проверка

Требуется Node.js 18+:

```sh
npm test
npm run check
npm run verify:models
npm run compare
```

Версия 0.7 прошла 15 тестов: 12 производственного движка и 3 сравнения сценариев; также проверен синтаксис девяти файлов. Проверены точная граница остановки через 45 минут, восстановление и импорт. Перенос двух моделей в JavaScript сравнен с сохранёнными предсказаниями Python на 20 443 отложенных записях: решения совпали, максимальная разница вероятностей меньше 10⁻¹⁰.

В версии 0.7 в Chromium проверены ползунок, обновление графика и таблицы, сохранение выбора при навигации и JSON-экспорт сравнения. Карточка помещается в ширину 390 px. Диагностика Scania и все шесть разделов проверены ранее в версии 0.6.1; артефакты моделей и вычислители прогноза не менялись. Подробности и ограничения — в [отчёте проверки](docs/verification.md). Маршрут обучения на внешней заводской истории CSV ещё не выполнялся. `npm run compare` воспроизводит сравнение сценариев из презентации; сохранённый результат — `data/scenario-comparison.json`.

## Границы прототипа

Данные заводской симуляции синтетические; схема и оборудование условные. Открытые данные Scania используются в отдельной диагностической демонстрации. Подключения к системам Allur нет. Импортированный снимок после запуска продолжает моделироваться, а не получать телеметрию предприятия. Модель считает ожидаемые количества; дефекты могут быть дробными. Выпуск завода берётся по финальной сборке, чтобы не учитывать одну машину несколько раз в разных цехах.

Прогноз баланса потоков и регрессия отражают упрощённый сценарий. Индекс риска — оценка по правилам, не вероятность отказа. Обученная модель прогнозирования поломок не реализована. До промышленного применения нужны реальные исторические данные, проверка прогнозов, интеграции, управление доступом и согласование терминов показателей.
