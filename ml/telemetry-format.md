# История производства для переобучения

Этот маршрут принимает внешнюю историю и готовит отдельную модель для анализа. Сейчас реальная история Allur отсутствует; импорт и обучение на ней ещё не выполнялись. Изменённые сценарии в этом обновлении не запускались и не проверялись тестами. Демо продолжает использовать ранее обученный синтетический артефакт.

## Формат CSV

UTF-8, разделитель — запятая, десятичная точка. Шаблон заголовка: `templates/telemetry.csv`. Одна запись описывает состояние финальной сборки; одна смена имеет один уникальный `episode_id`.

| Поле | Формат и значение |
| --- | --- |
| `episode_id` | Уникальный ID смены, например `assembly-2026-09-01-day` |
| `timestamp` | UTC: `2026-09-01T03:00:00Z`, также допускаются три знака миллисекунд |
| `buffer` | Неотрицательный запас комплектов |
| `demand_per_hour` | Положительный расход комплектов в час, известный в этот момент |
| `supply_per_hour` | Неотрицательная подача комплектов в час, известная в этот момент |
| `stopped` | `1` — линия остановлена; `0` — работает |
| `stop_reason` | При остановке: `buffer_exhaustion`, `equipment_failure`, `planned` или `other`; при работе — пустое поле |
| `intervention` | `1` — ручное пополнение или другое вмешательство в текущий момент; иначе `0` |

Перед экспортом переведите локальное время в UTC. Строки могут идти в любом порядке: подготовка сортирует их внутри смены. Дубликаты времени отклоняются. Нужны значения, доступные оператору в момент прогноза; средние потоки, вычисленные с использованием будущих точек, создадут утечку данных.

Рекомендуемый интервал — 5–15 минут. Признаки используют последние восемь точек, минимум три и минимум десять минут истории. Данные с более частым опросом сначала агрегируйте до подходящего интервала без использования будущих значений. Максимальный размер входа — 32 МБ.

## Подготовка

Храните исходную историю и результаты в `ml/local/`: эта папка исключена из Git и сборки архива.

```sh
mkdir -p ml/local
# Поместите предоставленный предприятием файл в ml/local/raw-telemetry.csv.
node ml/prepare-telemetry.js \
  --input ml/local/raw-telemetry.csv \
  --output ml/local/prepared-september \
  --train-end 2026-09-15T00:00:00Z \
  --validation-end 2026-09-23T00:00:00Z \
  --max-gap 15
```

Даты в команде служат примером. Выберите границы по фактическому диапазону истории **до оценки результатов**. Старые смены идут в обучение, следующие — в калибровку и выбор порога, последние — в отложенную оценку. Смена, пересекающая границу, исключается целиком. Каждое будущее окно также остаётся внутри своей смены и периода. Случайное перемешивание реальной истории не применяется.

Подготовка исключает:

- состояния, в которых линия уже остановлена или запас равен нулю;
- короткую историю, разрывы больше `max-gap` и неполные будущие 60 минут;
- окна, в которых оператор вмешался или произошла остановка по другой причине.

После вмешательства, остановки или длинного разрыва старая история сбрасывается. Положительная метка означает наблюдаемую остановку по причине `buffer_exhaustion` в следующие 60 минут. События между измерениями могут быть пропущены; для точных меток нужен журнал событий. Исключение окон с вмешательствами может создавать смещение: оператор часто реагирует именно на высокий риск.

Результат: `training.csv` и `manifest.json` с хешами входа и датасета, границами времени, списком смен и причинами исключения. Поле `source: observed` описывает заявленный тип входа; оно не подтверждает, что файл действительно получен от Allur.

## Обучение и графики

После установки зависимостей из `requirements.txt`:

```sh
.venv/bin/python ml/train.py \
  --data ml/local/prepared-september/training.csv \
  --manifest ml/local/prepared-september/manifest.json \
  --output-dir ml/local/trained-september
.venv/bin/python ml/plot-results.py \
  --results ml/local/trained-september/results
```

Для подготовки и обучения выбирайте новые пустые папки. Все три выборки должны содержать оба класса. Если этого нет, получите больше истории или измените границы с учётом заранее установленного протокола. Не подбирайте модель по отложенной оценке.

Артефакты сохраняются в `models/` и `results/` внутри указанной папки. Диапазоны входа берутся из обучающей выборки. Предупреждающий порог выбирается по полноте не ниже 85% на выборке настройки; если такого порога нет, обучение завершается с объяснением.

Внешняя модель автоматически в приложение не подключается. До подключения нужны подтверждение происхождения и причин остановок, достаточный будущий период оценки, анализ пропусков и ложных предупреждений и согласование порога с предприятием. Доверительные интервалы по сменам могут быть ненадёжны при малом числе смен и зависимостях между ними.
